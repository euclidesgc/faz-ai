# Projetar — react-e2e-tests

Use a entrega, os critérios do produto, o contrato da aplicação e os consumidores reais como entrada. Se faltar decisão que muda comportamento, registre a dúvida e avance no que independe dela.

1. Definir jornada, resultado observável e aspecto que exige navegador: navegação, foco real ou integração completa.
2. Escolher ambiente local e dados controlados, inclusive API simulada quando apropriado; não exigir backend real.
3. Definir isolamento, preparação e evidências de falha, incluindo screenshot/trace quando úteis.

## Entrega para a próxima etapa

Registre decisão e motivo, arquivos/contratos afetados, dependências e critério de verificação. Compare alternativas somente quando houver escolha relevante. Reutilize contratos da spec; não transcreva o catálogo inteiro no plano.

Verificação planejada: Jornada passa isoladamente em navegador com dados controlados e produz diagnóstico utilizável quando o comportamento falha.
